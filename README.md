# Brandloom

一个无需 Figma、无需 API Key 的本地营销物料适配原型。将品牌规则、已确认文案和产品素材组合为三个语言版本，并提供可检查、可修正、可复用的输出。

当前是确定性排版工具，尚未接入 AI 模型。它是独立实验项目，不是 Magnific 的源码或完整复刻。

## 立即运行

直接双击根目录的 **index.html**，在现代桌面浏览器中打开即可。不需要安装依赖，不需要启动服务器。页面不发送网络请求。

根目录 index.html 已打包所有 CSS 和 JavaScript，是可以独立复制和分享的运行文件。src/ 是便于二次开发的源文件。

## 已实现

- 品牌强调色、安全边距、标题字号范围、标题行数。
- 上传 PNG、JPEG、WebP 格式 Logo / 产品图；每张最多 4MB。
- 英文、德文、法文文案分别输入，保留原文，不自动翻译。
- 4:5（1080×1350）、9:16（1080×1920）、16:9（1920×1080）布局。
- 选一个尺寸生成三个版本，或选择全部尺寸生成九个版本。
- 检查画布、文案、价格、比例、安全区、标题行数与字号、指定对象色值。
- 明确区分通过、不通过、待人工判断。
- 调整标题位移、字号；保存为当前版修正、同尺寸模板偏好或品牌字号上限。
- SVG、PNG、检查报告、项目 JSON、自定义 DESIGN.md、含当前项目的离线 HTML 导出。
- 故障注入、浏览器自测、修改记录、实际时间对照记录。

## 推荐试用顺序

1. 不改演示素材，点击“生成三语言版本”。
2. 选中结果卡片，检查右侧报告。
3. 在“验证检查器”中注入一次产品拉伸，确认比例检查不通过；重新生成恢复。
4. 选德语版本，填写标题位移 / 字号及修改原因，保存修正。
5. 重新生成，验证修正继续生效。
6. 逐版完成视觉审核，尝试导出 SVG 和 PNG。
7. 导出项目 JSON，以便以后继续编辑。

导出项目保存输入、素材、规则、模板偏好和修改记录。重新打开或重新生成时，视觉审核确认会重置，避免旧确认套到新输出。

## 二次开发

只运行页面时不需要 Node.js。修改源码和运行命令行测试时，使用满足 package.json engines 的 Node.js 环境。

~~~sh
npm test
npm run build
npm start
~~~

不需要 npm install，本项目没有第三方运行或开发依赖。

- npm test：执行引擎测试。
- npm run build：将 src/ 重新打包为根目录 index.html。
- npm start：可选的本地服务器，仅监听 127.0.0.1，默认端口 4173。

修改源文件后重新构建。直接修改 index.html 的内容会在下次构建时被覆盖。

## 放到 GitHub

解压 ZIP，把 **brandloom 文件夹内部的文件**上传到你的仓库根目录。不要只上传 ZIP；根目录应直接看到 index.html 和 README.md。

如果启用 GitHub Pages，将发布目录设置为仓库根目录即可；页面无需服务端和构建服务。不要把浏览器地址栏的 data: 地址当作网站地址，它只是临时预览。

包里只有虚构 APEX 演示数据。你以后导出的项目 JSON 和离线 HTML 可能包含上传的素材与文案，公开仓库时请选择你有权公开的内容。

## 当前边界

- 内置三种布局，不支持任意 PSD / Figma / SVG 模板导入。
- 固定使用系统 Arial，700；没有打包或分发字体文件。系统字体回退可能影响排版。
- 文本宽度来自浏览器 Canvas，行框检查不能替代实际视觉复核。
- 只验证指定标题与 CTA 背景的色值，不验证位图颜色。
- 图片的比例检查针对图片对象的宽高比，不判断图片内产品本身是否变形。
- 矩形重叠只是审核线索，不等于真实像素遮挡。
- 不包含 AI 生图、自动翻译、自动抠图、官网 / PDF 规范提取。
- 规则以表单和项目 JSON 执行；DESIGN.md 是说明与导出，不是自动解析的输入格式，也不声明兼容第三方格式。
- 浏览器存储可能因配额或隐私设置失败，导出项目可作为备份。
- 审核结果是人为确认，不是自动视觉评审。
